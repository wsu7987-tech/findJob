# FineJob BOSS 执行器

这是 FineJob 的独立 Chrome 执行器。它与 FineJob 本机后端配对，负责受控执行 BOSS 默认招呼，并为首版自动代聊提供新消息观察、多标签页协调和人工确认后的文本发送。

## 当前能力

- WXT + Manifest V3 + Vue 3 + TypeScript 独立工程。
- MAIN → Content → Background 三层隔离通信。
- 通过 `127.0.0.1:8000` 与 FineJob 完成本机配对、心跳、队列同步和状态回传。
- 控制通道建立后由插件主动发送一次心跳，立即同步 FineJob 的插件联通状态。
- 输入配对码后，插件等待主动心跳完成，再确认配对连接状态。
- 插件重启后自动打招呼默认暂停，必须在插件面板点击“开始”。
- 显示当前任务、后续队列、页面身份、沟通状态、上次结果和风险状态。
- 支持开始、暂停，以及把尚未真实发送的动作退回待确认。
- 执行队列分为待执行和执行失败；失败动作支持单项或全部重试、撤销，结果未知仅回传 FineJob 并保留在记录中。
- 只在岗位 ID、登录状态和沟通状态通过交叉验证后执行。
- 真实动作固定为 `BOSS_DEFAULT_GREETING`，使用 BOSS 账号当前默认招呼语，不发送 FineJob 自定义文本。
- 单个动作只调用一次建立沟通接口；`code=0` 立即持久化为“平台已受理待验证”，FineJob回写失败只重试回调，不重试平台请求。
- 平台明确受理默认招呼请求后立即标记执行成功并进入下一项。
- 请求真正无响应时记录“未知错误”、移到展示队尾且不重试；连续3个不同岗位未知才暂停。频控、验证码、登录失效或页面错配仍立即暂停。
- 自动代聊监听、草稿生成和人工确认发送使用三项独立开关，默认全部关闭。
- 监听开启后，只观察新出现的 `chat` MQTT/Techwolf Protobuf 消息，不拉取 BOSS 历史聊天。
- 联系人和岗位映射使用单联系人元数据接口，不把联系人列表当作聊天历史同步。
- 同账号多个沟通页使用 Background 中的 5 秒心跳、15 秒候选失效和 20 秒租约选举一个领导标签页；租约按账号隔离并持久化于 `storage.session`。
- 只有领导标签页上报入站正文和领取发送动作；任意标签页上的人工出站消息会触发对应会话人工接管。
- 人工确认后的文本发送使用 BOSS `wt`、MQTT 连接、Protobuf 文本消息和 `chat` 主题发布方式。
- MQTT `publish` 未抛错只回写 `accepted`（界面文案“已提交发送”）；失败或未知结果均不自动重试。

岗位页面的打开由 FineJob 通过专用 Chrome 的 CDP 完成，插件不自行导航下一岗位。普通“在专用浏览器打开”只用于查看，不会创建或执行打招呼动作。

## 安装与构建

```powershell
pnpm install --config.offline=false
pnpm run typecheck
pnpm run test
pnpm run build
```

Chrome 未打包目录：

```text
.output/chrome-mv3/
```

## 在 Chrome 中加载

1. 打开 `chrome://extensions`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择 `.output/chrome-mv3`。
5. 打开或刷新 FineJob 专用 Chrome 中的 BOSS 页面。
6. 在 FineJob 待确认页生成六位配对码，再输入插件面板。
7. 核对插件队列和当前岗位；插件通过“开始”处理已批准队列，需要暂停时点击“暂停”。
8. 使用自动代聊时保持至少一个 BOSS 沟通页打开，并在 FineJob“自动代聊”页面分别开启所需权限。

## 运行流程

```text
FineJob批准岗位
→ 插件同步权威队列
→ 用户点击开始
→ FineJob打开队首岗位详情页
→ 插件核对岗位身份与沟通状态
→ FineJob记录dispatch_started
→ 插件单次执行BOSS默认招呼
→ code=0时插件先持久化并回传accepted，FineJob标记执行成功
→ FineJob随机等待1～3秒后处理下一岗位
```

页面打开后30秒没有插件状态时，FineJob检查插件和浏览器。双方正常且尚未真实发送时，当前岗位最多一次移到队尾；第二次超时后阻塞该岗位。真实请求开始后结果未知时禁止重试该岗位，但会释放执行槽并在队尾显示；连续3个不同岗位未知才暂停。

自动代聊流程：

```text
用户开启消息监听
→ 沟通页领导标签观察新消息并去重上报
→ FineJob 生成草稿
→ 用户二次编辑并点击确认发送
→ 后端执行版本围栏并创建一次发送动作
→ 领导标签页通过 MQTT chat 主题提交文本
→ accepted / failed / unknown 回写本地会话
```

## 安全边界

- FineJob SQLite 是唯一权威队列；插件本地不保存第二套业务队列。
- 配对令牌只保存在扩展存储与 FineJob 本机数据库校验数据中，不发送到 BOSS 页面。
- BOSS token 只在 MAIN World 发起单次平台请求时使用，不回传 FineJob，不写入插件面板或日志。
- 不读取 BOSS 历史消息；监听关闭时不解析或持久化新消息正文。
- 不自动确认 AI 草稿；自定义文本只能来自用户点击确认的当前版本草稿。
- 不自动发送简历、图片、联系方式或面试操作。
- 不处理或绕过验证码、登录失效、频控和平台安全机制。
- 不使用可信事件伪造、webdriver隐藏、随机鼠标轨迹等反检测手段。
- 每条自动代聊真实文本都必须由用户在执行当时点击确认。
