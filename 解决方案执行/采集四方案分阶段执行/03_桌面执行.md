## B1：提交、加载与独立请求修复

### 进入条件与范围

G0 明确范围和批准；与 A1 并行。主要文件为 `BossCapture.vue`、`fineJobBossCapture.ts`、`fineJobPlatformSessions.ts`、`SmartCaptureConfigForm.vue`、`types.ts`、`services/api.ts`。

### 实施顺序

1. `captureJobs` 加请求结束复位，覆盖成功、拒绝、异常、容量检查提前返回；保留启动意图未知时的重复提交限制，Loading 与“待确认”分别表达。旧页面/旧请求结果沿原归属检查处理。
2. 城市、策略、模型各自加载；模型目录仅在确需模型配置时加载，同次请求合并，已有模型值、失败后手动输入保持。不得由 45 秒目录请求覆盖整个配置区。
3. session 操作返回完整 session 后同时更新 sessions 与 bossSession，保留其他平台条目；删除立即重复 list。缺失响应的兼容行为明确一次性处理。
4. 详情单行、批量、抽屉统一提交状态；Store 在递增请求代次前拒绝重复提交，避免先前成功请求失去写回资格。Loading 只在对应岗位显示，提交失败保留选择。
5. 按 C1/C2 和 A1 接口样例补活动、质量、版本、时间及 pacing 类型/API 声明。允许开发纯展示映射，不提前删除尚未接通 SSE 的运行同步路径。
6. 为后续页面合并保留原 UI 方案的字段与操作映射，B1 只处理上述局部行为。最终结构在 B3 完成。

| B1-02 | 模型请求慢或失败，城市/策略已返回；不打开模型配置 | 已可用控件可操作；模型局部错误；无需模型时没有目录请求 |

## B2：SSE 消费、时间校准、确认预算与采集节奏界面

### 进入条件与范围

G1 整体 PASS，A1 的服务端首帧及持久版本已验；本阶段已批准。A2 并行。

主要文件：`fineJobBossCapture.ts`、`fineJobSmartCapture.ts`、`collectionStart.ts`、`App.vue`、`BossCapture.vue`、`StrategyManagement.vue`、`types.ts`、`api.ts` 及必要显示组件。B 独占这些文件。

### 实施顺序

1. 消费自定义和智能完整快照；按来源任务/scope/版本应用状态，处理相同版本的时间基准刷新。页面任务切换释放自己的订阅，智能自动控制器应用级监听按原生命周期保留。
2. 接好首帧、重连、手动同步及错误提示后，删除自定义周期 GET、智能 `scheduleRecovery` 持续 GET 和无限启动重试。onopen 只更新连接状态，版本跳号直接使用完整快照；loaded=true/current=null 是已成功读取。
3. 实现 C1 的服务器相对剩余时间＋客户端单调计时；计时只更新本地视图。暂停/停止/终态清理活动，正式 JD 与分析并行时分别展示，预取归属独立。
4. App 负责唯一 restore，页面立即消费已有 receipt。保存 operation 的自动已用次数；提交中、异常自动 check、恢复首次 check 及后续定时 check 共用最多 6 次，按 1/2/5/10/15/15 秒调度。进行中查询合并，只计实际自动发起的请求，手动按钮不重置自动预算。
5. 到限停自动确认并保留未知意图，迟到的真实启动响应仍可完成确认；started/rejected/dispose 停止。手动查询完成不能复活定时器。合并 receipt 已确定后的结果读取。
6. `StrategyManagement.vue` 增加采集节奏页签，使用 A1 pacing GET/PUT；两个秒数区间、下限、恢复默认和“新任务生效”提示。采集页展示运行任务实际快照，估算使用配置和剩余工作；已有输入、投递执行间隔配置保持职责。

### B2 必检项

| ID | 场景 | 必须观察到 |
| --- | --- | --- |
| B2-01 | 建立/重连/current=null/跳号/相同和旧版本 | 完整快照恢复，旧版不覆盖，跳号与 onopen 不发额外 GET，相同版仅可校准时间 |
| B2-02 | SSE 断线、无 EventSource、地址失败、GET 失败 | 保留结果和错误，结束请求 Loading，手动同步可用，无周期任务 GET/无限恢复 |
| B2-03 | 页面卸载、模式/任务切换、恢复详情阶段 | 对应连接释放/重建，旧回调不串任务，应用级智能控制监听仍有效 |
| B2-04 | 客户端时钟快/慢 5 分钟，运行中调整墙上时钟 | 本地剩余时间正常递减；0 后不自行换活动、不发 GET，服务端新状态才推进 |
| B2-05 | 页面后台再前台、重连收到相同业务版本 | 重算当前剩余时间，无长期停住/负数，无重复计数 |
| B2-06 | 启动提交持续 180 秒、异常触发自动检查、恢复应用 | 同 operation 自动请求总数最多 6，实际间隔符合约定；恢复不重置；手动查询独立 |
| B2-07 | 预算耗尽后手动查询、迟到 started、App 已恢复后进页面 | 手动不重启预算，迟到响应可消费，页面不重复 restore/读取同一结果 |
| B2-08 | pacing 非法范围、固定值、恢复默认、修改后观察新旧任务 | 前后端同下限；当前任务显示旧快照，新任务用新值；保存/错误状态准确 |
| B2-09 | cooling 与范围切换、终态、计数未知 | 进度不清零，同 scope 分母准确，未知总量不用伪百分比，终态保留摘要 |
| B2-10 | A1 服务端真实接口＋B2 Store 最小联通 | GET/SSE 首帧结构可消费，配置读写往返正确；测试替身与实际响应无差异 |

获批后以假定时器、网络替身和真实本地后端隔离数据验证。B2-10 由总控协调单一后端实例或预定独立实例，不能与 A 的实例争用。

## B3：TUI 轮次接续与最终页面

### 进入条件与范围

G2 整体 PASS；本阶段已批准，A3 并行。分析样例与 C5/C6 一致；有契约调整由总控同时通知 A/B。

修改范围包括 `workflowCodexHandoff.ts`、`fineJobWorkflowCodexController.ts`、`electron/codex-session.ts`、现有 Electron 桥接及 renderer 终端状态服务、分析 API/类型/Store、`BossCapture.vue` 和必要共用组件。外部协议/依赖遇阻时立即报告，不替换已确认通道。

### 实施顺序

1. 优先核对现有终端桥接能否提供本轮结束/可接收信号，记录其身份、来源、时序和重连行为。仅进程 running 或输出停止不能放行。此项失败会阻断 TUI 连续自动交接，尽早报告用户。
2. 交接依据 ready 分析批次及独立执行能力，解除采集 completed/stopped/failed 对合法人工批次的整体排除；补齐创建后 handoff 摘要，按实际批次归属处理自动/手动启动及恢复。
3. 下一批同时等待结果收齐、终端可接收和配置允许；正式 JD 仍运行时可交接分析，ACK 不误启动竞争详情。会话不可恢复、提交失败、开始待确认分别展示；通道切换依据服务端释放结果。
4. 分析面板共用首次/失败重试/重新分析范围，完整登记 12 岗展示 5/5/2，已有批次定位原入口。自定义/智能、单岗/批量都依据实际资格；显示跳过、处理中和视图外选择数量。
5. 分析独立版本/SSE/来源订阅，采集终态仍更新批次与岗位，保留原最终摘要。采用平台 ID 与历史记录 ID 映射，未匹配 Item 显示同步占位及手动同步。
6. 原 UI 方案的最终布局落地：会话条、任务摘要、模式工作区、统一岗位区；智能时间线消费 A2 搜索原因及 A3 并行状态。重复区域迁移完毕再移除。
7. 逐项实施原 UI“现有内容与优化后位置映射”：目标当前/目标/剩余、页数/新增/续采、候选/正式/预取、全部配置开关、完整分析/投递字段、反馈、来源链接、Context、高级信息、父任务控制及返回驾驶舱。
8. 辅助列可恢复、既有排序与多岗展开摘要保持；统计来自完整任务集合，筛选只影响行，选择/排序在结果更新中保持，切任务/模式清空选择。终态零岗位隐藏空表格，筛选零匹配保留筛选入口。
9. 活动与分析双进度、容量等待、搜索耗尽收尾、旧输入结果提示、动作 Loading 与不可执行原因均有可操作入口。

### B3 必检项

| ID | 场景 | 必须观察到 |
| --- | --- | --- |
| B3-01 | 真实已获批的 TUI 轮次结束与下一次提交 | 可接收状态来源有证据、身份对应当前任务/会话/轮次；不会因进程存活或固定等待误提交 |
| B3-02 | 结果收齐与终端结束两种先后顺序、用户批后等待 | 两事实及配置同时满足才提交；原会话可用时复用，丢失时显示恢复入口 |
