## C1：时间与持久化版本

### 活动与时间

采集范围包含原有 `scope_id` 及 `activity / activity_scope / activity_message / activity_started_at / activity_deadline_at`。有截止时间的冷却才显示数字倒计时；未知时长活动显示实际状态。

GET/SSE 快照信封增加 `server_now`，为快照发送时服务端带时区时间。初始帧与重连首帧重新生成该时间；队列只保存最新业务快照，发送时补时间，避免拿旧采样时间计算新的剩余值。单纯发送时间变化不增加业务版本。

客户端收到时记下 `performance.now()`，初始剩余值为 `max(0, activity_deadline_at - server_now)`，以后扣减客户端单调经过时间。相同业务版本的重连首帧可刷新时间基准，同时保持计数不重复应用。该方式消除客户端墙上时钟偏差；显示仍可能包含传输延迟，作为展示值使用。归零后由服务端决定下一动作，不启动新的请求或采集。

服务端实际等待采用可中断等待和单调经过时间；恢复时由保存的截止时间计算剩余值，已过期直接进入下一允许动作。同一次冷却只抽取一次时长。停止、暂停、中断、终态清理公开活动，恢复所需内部时间保留。

### 版本

- 智能采集复用 `fj_smart_captures.state_version`，版本与可见状态一同提交后发布。
- 自定义在 `fj_boss_capture_batches` 增加持久化 `state_version`；阶段接续、详情阶段及重启恢复读取已保存值再递增，不能从内存默认值重新起步。
- 独立分析保存自己的 `analysis_state_version`，与批次状态一起持久化；采集终态不阻止分析版本更新。
- 前端按任务或分析批次身份比较版本；新身份重置比较基准。同身份旧版本忽略，相同版本合并，较新完整版本允许跳号。
- 服务端先订阅，再读首帧；已订阅期间积压的旧快照由版本判定处理。进程重启时，正在运行而执行器已丢失的任务先进入明确的恢复状态并递增版本；不得发布伪造 running 活动。
- 历史自定义任务初始化持久化版本为 1；若无法恢复为完整任务，返回明确不可恢复原因，前端结束加载并保留已有结果。重启恢复能力不得用版本重置替代。

## C2：采集有效性与页面身份

### 采集器必须提供的事实

内部采集结果增加 `capture_validity`，取 `VALID_NONEMPTY / VALID_EMPTY / INVALID / PARTIAL_INTERRUPTED`；同时包含 `validity_reason`、`filters_confirmed`、`range_complete`、实际成功页数和 `has_more`。这些是结果质量字段，原任务生命周期枚举保持。

每页内部记录：任务与组合 ID、逻辑采集窗口 ID、浏览器目标与导航代次、网络 requestId、实际 keyword/city、平台筛选、分页参数、业务结果、原始岗位数和成功保存位置。只保留业务判定需要的信息。前端消费汇总质量、原因和计数；浏览器内部引用不随公开快照发送。

1. `NetworkJoblistCapture` 保存请求的 URL/查询参数及必要请求体，使用同一 requestId 关联完成事件和响应体；关键词、城市、筛选平台编码与当前组合一致，分页位置为本窗口预期页。
2. 仅接口路径匹配、地址栏匹配、HTTP 成功均不足以确认筛选。以平台请求中实际生效的参数及业务响应为主要证据；无法映射的筛选必须取得页面已选标签等可解释证据，仍不能确认则判 INVALID。参数命名映射须由现有资料或获准采样证实。
3. 业务成功、岗位数组结构正确、解析成功且保存完成，才增加 `succeeded_pages`。空数组也是成功页；缺字段或错误响应不转成空数组成功。
4. `hasMore=false` 是可信末页的证据之一；任何空页都先核对业务成功。空数组但仍有更多页面时，在剩余计划内继续并执行冷却。没有平台明确空结果或完整有效计划结束证据的零数据，保持无效/未完成。
5. 超时、业务失败、解析失败、筛选不明、登录或验证错误都中断。先前有效数据及筛选结果保留，当前窗口不结算搜索连续次数。

### 窗口与恢复

`window_id` 表示一次计划执行的首批或续采批次；暂停和异常恢复保持该身份，正常完成后另行续采使用新身份。成功页计数和页增量以窗口及已确认分页位置去重，requestId 辅助定位一次网络响应；恢复中 requestId 改变而页面相同也不能重复计数。

`attempted_pages` 在实际发起导航/滚动时增加；`succeeded_pages` 在有效页保存后增加；`failed_pages` 统计明确失败尝试。执行中可以有未完成尝试，不要求三个数始终相加相等。原 `pages_loaded` 与列表主进度对应成功页数，累计成功数从已保存页增量得到。

恢复前核对最后已保存页与下一待处理页；无法确认时显示保留结果、重新开始入口。异常批次恢复后完整结束才结算一次；迟到响应、重复回调、重新订阅均不重复入账。

`ZERO_RESULT` 需要本窗口有效结束且组合累计岗位数为零。已有结果组合本轮零新增按边际产出处理。`INVALID` 与 `PARTIAL_INTERRUPTED` 保持空组合预算及低产出连续次数。

## C3：Fresh、本任务新增与边际指标

### 固定样本集合

- `R`：最近完整窗口的有效页中按稳定岗位 ID 去重后的返回岗位集合；同岗在不同窗口再次返回，仍进入该窗口的 R。页面响应重放不增加 R。
- `N`：R 中首次归属本任务的岗位集合；对应 `marginal_jobs_seen = |N|`，跨组合也按本任务首次发现判断。
- `F`：R 中沿现有历史重复标志认定为 Fresh 的集合。历史判定采用该采集关联记录已保存的值；全局采集次数日后增长不回改已结算窗口。当前源码还将 `processing_state=duplicate` 归为历史重复，适配时保留含义。
- `Q`：F 中未被岗位历史冷却排除、最终筛选为 pass 或 review 的岗位，沿现有 `build_metrics_for_window` 资格；详情采集间隔与岗位历史冷却排除分别处理。

低新鲜度比例为 `|F| / |R| < 0.25`；合格 Fresh 比例为 `|Q| / |F| < 0.15`，后一分类仅在 F 非空时计算。`marginal_fresh_jobs = |F|`、`marginal_qualified_fresh_jobs = |Q|`。**不能把 |N| 替换成 0.25 的分子。** UI 新/历史岗位继续采用原历史口径；新加入本任务数量单独显示。

本窗口 N 为空且组合累计已有岗位时，按既定“无新增”规则计一次低新鲜度，即使该历史关联中的 Fresh 标志仍为首次采集时的值；证据原因记 `no_growth`，不能伪称比例低于阈值。两个低产出分类各自累计，恢复正常则清零本分类，任一达到任务的 `low_yield_streak_limit` 才触发相应切换。两类同时触发同一窗口仍只决策一次。

例：R 有 20 岗、N 有 10 岗，其中 Fresh 为 2 岗，则新鲜度为 2/20，不是 10/20。前一窗口新采的 20 岗在后一窗口全部重现时，N=0，以 no_growth 连续计数判断，不能被早期合格结果永久驱动滚动。

每页筛选完成有对应记录，批末等待本窗口筛选收敛。组合总量按唯一岗位及成功页累计，窗口计数按完成窗口累计；禁止把包含旧岗位的累计快照再次作为新增数据相加。Engine 现有两类连续计数继续复用，修正输入和结算身份。

## C4：搜索证据、预算和放宽

Scope 为当前任务中的关键词＋城市，顺序为当前关键词下城市顺序，再下一个关键词。Baseline 为策略允许且平台可表达的最宽条件。关键词、城市与所有保留筛选参与证据匹配。

正向证据须满足下列一种：

1. 同任务、同词城、同策略输入下，已有实际岗位同时满足候选维度值与**所有保留筛选**。只有行业频数、学历缺失或不匹配，不能证明行业＋学历交集。
2. 相同完整候选条件的有效历史组合曾有岗位；父组合 ID 记录来源，适用性按实际条件逐项比较。相同组合已执行时优先复用其结果。
3. 平台对完整相同条件有已确认的正数提示；只看到宽范围提示不算。当前采集器若未实现此证据来源，就使用前两种。

证据键为任务、词城、策略输入版本或已保存值、规范化保留条件、目标维度与值；同时保存来源组合/页/岗位。多选条件按集合含义比较，空值和不限统一；未知值不作肯定匹配。复用现有组合标准化能力。

负向证据仍限定已确认为空的交集，禁止从该空组合继续增加筛选。宽范围空结果向更窄条件传播需要额外平台语义证明，本轮不新增传播功能。

放宽必须在策略范围内。已有父组合复用不采集、不消耗预算、不重置连续空次数；未执行的更宽组合真实完成且为空，计入连续空次数。非空有效搜索重置；异常不改变；只创建组合不计完成次数。Scope 连续可信空组合上限 2，组合总预算 24，两者分别记录。

防止重复探索：所有候选先核对完整组合是否已执行；已执行父组合只改变决策上下文。候选逐个检查，同维度首选已执行时继续检查其他有依据值。放宽后的收窄须有当前有效拒绝分布/覆盖证据和新组合，沿用已有搜索规则；自动永久禁用该维度尚未纳入。

## C5：分析供给、结果与 TUI 接续

自动流程同一任务只有一个进行中的分析分组和一条浏览器采集链。当前正式 JD 轮次最多 B 岗，下一批预取最多 P 岗，B/P 沿现有配置及候选限制。本轮新增自动就绪/待处理 JD 范围不超过 B+P；每个小分析批次不超过配置批大小。

预取的唯一归属是**当前正式 JD 轮次**。不能因首条 JD 拆出多个分析批次，就给每个小批 ACK 都生成一份 P。正式详情未结束时 ACK 仅确认分析启动；正式详情结束且原条件满足后至多准备一份下一批。

分析慢时允许完成已登记的 B 与至多 P，达到供给范围后等待分析和批后条件；不继续扩充新的自动列表/详情范围。分析完成、容量释放且配置允许继续后，由事件接续。已有历史 JD 不因分析排队重复采集。

用户一次选中 12 岗、批大小 5，完整登记 12 并拆成 5/5/2；该人工已确认范围可以大于 B+P，按相同单分组执行限制推进，不能截掉后 7 岗。人工与自动共用任务执行能力及同岗重复执行限制，人工登记不会授权扩充自动采集。

输入受理时保存 JD、简历、策略、补充要求的实际值或可读取版本，失败重试沿用。成功覆盖当前业务结果，失败保留。输入变化时旧结果标记依据，与目标输入不匹配则仅作参考。两个通道共用结果选择规则和执行归属，晚到旧执行结果不能覆盖新执行结果。

TUI 下一批的条件为：结果收齐或明确失败结论＋本轮终端处理已结束且可接收下一条指令＋任务控制与批后配置允许。当前 `codex-session.ts` 的进程 running、提示写入成功、ACK、输出暂时安静均不能单独作为轮次结束事实。

B3 必须给出项目现有终端事件/会话协议中可验证的就绪来源及运行证据。若无法获取，G3 不放行，向用户说明受阻及可选方案；不得自行把 TUI 退化为仅手动、切换 Exec 或凭固定延迟提交。任何替代方案需用户决定。

## C6：存储升级与恢复

复用 SQLite 和 `Database.initialize` 的增量升级模式。活动字段放现有进度结构，不为五个活动字段逐个新建列。以下存储清单随对应阶段实施：

| 阶段 | 对象 | 保存内容与旧数据处理 |
| --- | --- | --- |
| A1 | 新增专用采集节奏单例表 `fj_boss_capture_pacing` | 单例 ID、列表/详情最短与最长秒数、更新时间；不存在时提供默认值；不混入投递执行器间隔配置 |
| A1 | `fj_boss_capture_batches` 增量字段 | `state_version`，`pacing_snapshot_json`，`progress_json`；后者保存公开进度及恢复必需页面位置/内部冷却信息，公开响应仅选择允许字段；旧记录按兼容默认读取 |
| A1 | `fj_smart_captures.execution_config_json` 及既有进度 JSON | `capture_pacing` 启动快照和内部截止时间；子任务继承，旧任务缺字段用默认值，不能套用后来修改的全局值 |
| A2 | 现有搜索任务 payload/result、组合 evidence 及发现记录 | 窗口/页面结算、筛选完成、证据、两类连续次数；优先复用已有结构，明确窗口完成只结算一次 |
| A3 | 现有分析任务及交接持久化结构 | 完整人工登记范围、固定分组、输入、结果引用、版本、来源、轮次供给归属；自定义也有稳定 owner。实施前在 A3 记录明确表/字段落点及现有约束适配 |

A3 的实际表结构需要先对照现有任务 owner 与交接约束，不能只在前端伪造自定义分析归属。若现有表需要增量列/专用批次表，A3 在首次更改前把最小存储映射写入该阶段记录，确认包含于批准范围后实施。

新增表/字段遵循默认读取、增量添加、重复初始化稳定；保存配置与启动时复制配置分别在短事务内完成。发布状态发生在提交之后。

回退采用应用代码与读取行为回退，新增表/列及已保存业务数据保留。旧版不认识的新分析执行状态应先停止产生新执行并完成或人工处理已有执行，不能直接让旧调度器接管。数据恢复仅用于用户明确批准的数据库副本；不删除用户数据来“回滚”。

迁移验证必须在隔离数据库覆盖：空库初始化、旧结构升级、有历史任务默认读取、重复初始化、配置修改后运行任务仍用原快照、重启版本不倒退、升级失败后旧数据仍可读取。生产库升级安排放入 G4 的明确批准范围。

## C7：每阶段记录与放行规则

必检项须记录：编号、输入场景、实际行为/关键数量、验证方式与命令、结果、证据位置、未解决问题。设计案例的预期不能当成实际结果。新增自动化仅覆盖实际行为和风险分支，优先扩展已有验证文件。

结果状态为 PASS / FAIL / NOT_RUN / WAIT_APPROVAL。任何必检项不是 PASS 就不能进入后继阶段。阶段通过需要该阶段 A、B 记录齐备及 04 总控记录放行。

静态阅读、类型检查、替身验证、真实运行各自说明。真实平台筛选映射和 TUI 轮次就绪若缺可验证资料，相关门槛保持未通过，取得有限范围采样授权后再补证。不得以全量测试替代这两个外部事实。
