# 12 / P0F：浏览器与登录启动检查

本次新增执行任务，依赖 01 的超时与请求状态能力。

## 1. 当前实现与复用点

| 文件 / 符号 | 已有能力 | 本次接入点 |
| --- | --- | --- |
| fineJobPlatformSessions.ts | 手动打开浏览器、检测登录及 loading | 复用动作及会话展示 |
| boss_scraper/service.py 的 get_browser_status | 浏览器运行、目标 URL、是否搜索页 | 同时判断进程和目标页面 |
| start_browser、open_login_page | 启动专用 Chrome、打开目标页 | 浏览器或目标页缺失时调用 |
| boss_cdp_raw.py 的 check_login_state | 创建临时探测页、捕获搜索响应、返回结构化结果 | 作为本轮登录判定的依据 |
| boss_capture.py 的 start_boss_capture | 目前仅判断浏览器 running | 创建自定义任务前检查就绪 |
| smart_captures.py 的 start_independent_capture、_start_new_batch | 目前仅判断浏览器 running | 创建身份、启动批次前检查就绪 |

实际函数名以实施时当前代码为准。直接复用现有浏览器 profile、CDP 和采集器，不引入浏览器自动化依赖。

## 2. 前端启动顺序

1. 校验当前模式的表单。
2. 立即设置 starting，防止容量检查期间重复点击。
3. 读取现有活动采集任务；有冲突则显示已有提示，结束 starting。
4. 显示“检查浏览器”，读取实时浏览器状态。
5. 浏览器未运行时启动；浏览器运行但没有可用 BOSS 页面时打开页面；已有有效目标页时保留。
6. 显示“检查登录状态”，调用对应采集启动接口，由后端完成本次实时探测并在成功后创建或启动任务。
7. 成功取得身份后读取服务端 current 或自定义任务，切换为真实采集阶段。
8. 失败在启动区显示原因及操作入口，finally 释放按钮状态。

浏览器未打开时“开始采集”仍可点击。禁用条件仅来自表单无效、正在提交、已知执行容量冲突或当前控制能力。

前端不在启动接口之前额外调用一次完整登录探测。后端的启动检查承担本次实时登录校验，避免一次点击连续探测两次。手动“检测登录状态”入口保留。

## 3. 后端检查顺序和边界

在现有 BossScraperService 内集中复用浏览器与登录逻辑，调用结果保留结构化分类。各启动入口调用同一检查逻辑。

- 先验证参数和已有执行容量，再执行可能较慢的浏览器与登录检查。
- 浏览器或有效目标页在请求间关闭时，尝试重新打开一次，打开失败返回明确错误。
- 从 check_login_state 获取本轮实时结果，不以数据库中旧 ready 值直接放行。
- 检查成功后通过既有容量入口创建或恢复任务，实际启动仍重新校验容量。
- 同一启动调用链只探测一次。start_independent_capture 内部继续调用 _start_new_batch 时复用此次就绪结果；该复用只在当前服务调用中生效，不形成客户端可伪造的跳过参数。
- 已有 pending、resume、retry、继续列表和手动详情入口，在确实要启动浏览器采集前复用检查。纯暂停、停止和结果查看不调用登录探测。
- linked 路径先遵循父任务执行权校验；未获执行权时不打开浏览器或推进采集。
- 不将此检查插入每次轮询或每页采集。采集运行期间沿用采集器已有的登录失效与风控处理。

独立任务首次创建应在探测成功之后进行。对已有 pending 或恢复任务，检查失败保留原有可恢复身份；具体状态变化遵循已有状态机。

## 4. 登录结果分类

现有 LoginProbeStatus 已区分 available、unauthenticated、restricted、empty、response_error。service.check_login 目前将其包装为布尔值；启动检查需保留底层分类，可通过服务层增加结构化返回再复用原包装。

| 本轮结果 | 启动行为 | 用户文案方向 |
| --- | --- | --- |
| available | 继续创建或启动 | 登录检查通过 |
| unauthenticated | 启动失败 | 任务启动失败：BOSS 尚未登录，请登录后重新开始 |
| 本轮探测或采集目标被重定向到 /web/user/ | 启动失败 | 任务启动失败：BOSS 尚未登录 |
| restricted | 启动失败 | 任务启动失败：BOSS 访问受限，请在浏览器中处理验证 |
| empty | 暂不启动 | 暂时无法确认登录状态，请检查页面后重试 |
| response_error、探测超时 | 启动失败 | 登录检查未完成，并显示超时或响应异常原因 |
| 浏览器或页面打开失败 | 启动失败 | 浏览器或 BOSS 页面打开失败，并给出可操作原因 |

URL 信号只针对本轮实际探测或准备采集的目标页，校验域名与路径。旧登录标签仍打开时，以本轮有效探测结果判定，避免持久登录可用却被旧标签误判。

需要在探测页导航发生重定向时记录其 URL，复用现有 CDP 能力。不要访问所有标签并把任意登录页当成当前任务未登录。

## 5. 响应与状态

- 沿用 AppError 的 HTTP 错误及 error_category；添加必要的明确分类，不新增系统级健康接口。
- 首次启动检查失败，不返回 running 身份，不提示“任务已启动”。
- 若已有任务身份，则返回可解释的检查失败，页面保留已有结果和恢复操作。
- 任务创建成功但后续页面刷新失败，显示“任务已启动，状态同步失败”，提供同步入口。
- 写请求超时先查询 current 或活动任务确定是否已经创建，再决定下一步。
- 启动失败属于本次用户动作；已有任务结果与其分别展示，不能把旧结果改成失败。

## 6. Loading 和交互

检查浏览器、打开浏览器、检查登录使用本次 starting 阶段展示，相关按钮持续 loading。概览与列表仍展示同一模式已有的任务结果。

未登录时保留浏览器供用户完成登录。页面提供“打开 BOSS 浏览器”或“重新开始”入口；用户登录后重新点击即可，不要求刷新应用。

前端不等待人工登录完成，也不自动重复创建任务。

## 7. 授权后的验收

对应 08 的 ST 项：

- 浏览器未打开可直接点击开始，并执行打开。
- 浏览器运行但目标页关闭时能恢复目标页。
- 已登录成功启动；未登录和本轮重定向明确失败。
- 受限、空样本、超时不被统一标注未登录。
- 容量冲突优先返回；连续点击只提交一次启动。
- 探测成功后才创建首次任务；pending、恢复、详情入口遵循既有权限。
- 登录检查超时后按钮恢复；登录完成后可再次点击启动。
- 直接调用后端入口仍经过同一检查。
