# 05 / P0E：采集页面、阶段进度与区域 Loading

本次主要交付任务。请求可靠性依赖 01，启动阶段接入 12，共享实时数据接入 02。原包要求先完成分页、增量协议和 Context 迁移的依赖取消。

## 1. 页面布局

建议从上到下组织为：

1. 简洁环境状态：浏览器、登录、刷新和打开入口。
2. 智能 / 自定义模式切换，位于该模式所有内容之前。
3. 当前模式的任务状态与阶段进度；未启动且无任务时隐藏。
4. 当前模式的岗位结果；智能模式增加分析队列与结果。
5. 采集配置和启动 / 控制区：无任务时展开；执行期间保留当前参数摘要及允许的操作；终态保留重新采集入口。
6. 执行详情、智能搜索策略、父任务关系和高级 Context 工具，按适用条件显示并折叠次要信息。

无任务时以配置和开始操作为主要入口。已有结果时优先展示状态与结果。配置区默认折叠只改变展示，保留用户输入和现有校验。

历史查看保持已有查询能力，放入智能模式高级工具；不将历史查询对象写成当前任务。

## 3. 数据归属

建立单一当前显示任务选择入口，输出当前模式、任务身份、状态、阶段、进度、岗位、操作能力和错误。

- 智能模式只读取共享 Smart Capture Store 的 current；无 current 时显示智能模式无任务。
- 自定义模式只读取 capture_source 为 custom 或现有规则确认属于 custom 的任务。
- 不因一个模式缺少任务而回退到另一个模式的数据。
- 概览、进度、岗位表、导出路径、详情抽屉和操作区使用同一 owner。
- 切换模式或任务时，清理旧 owner 的行选择和已打开详情；切回同一任务可读取其已保存结果。
- 另一个模式有活动任务时，只显示容量冲突提示和切换入口，禁止混入它的任务概览与岗位。
- 当前 Smart Capture 与历史 Workflow 对象继续隔离。

## 4. 三类状态

### 请求状态

表达区域数据请求是否结束：idle、loading、refreshing、success、error。

### 业务阶段

表达采集当前工作：准备启动、检查浏览器、打开浏览器、检查登录、列表采集、详情采集、分析或收尾，以及等待、暂停、正在停止、中断、停止、失败、完成。

展示阶段由前端启动动作及已有 status、stage、waiting_reason、control_status、capabilities 映射，不要求后端更改状态枚举。

### 内容状态

对应区域处于 hidden、content、empty、error 中的适用状态。首次请求期间展示 loading；成功返回后才判断空内容。任务正在执行但尚未产出时展示等待结果提示。

## 5. 阶段映射规则

按当前 owner 建立集中映射，避免各组件单独推断：

| 事实 | 展示 |
| --- | --- |
| 本次启动正在检查环境 | 对应检查阶段，按钮 loading |
| 自定义 queued / list_continue_queued | 等待或准备列表采集 |
| 自定义 list_collecting / list_continuing | 列表采集中 / 继续列表采集 |
| 自定义 details_collecting | 详情采集中 |
| 自定义 stage 为 list_paused / details_paused | 已暂停，即使 status 为 completed |
| 自定义 stage 为 list_stopped / details_stopped | 已停止，即使 status 为 completed |
| 自定义 stop_requested 且仍执行 | 正在停止，保留当前计数 |
| 自定义 failed | 执行失败，保留结果与失败原因 |
| 正常 list_completed / details_completed 且阶段任务结束 | 本次列表 / 详情采集完成 |
| Smart Capture 当前批次正在列表或详情采集 | 显示对应实际采集阶段 |
| Smart Capture waiting_codex 或分析等待 | 等待分析 / 分析中，按实际数据映射 |
| Smart Capture paused / interrupted / waiting_for_user | 暂停 / 中断可恢复 / 等待用户，按原因和能力给操作 |
| Smart Capture stopped / failed / completed | 展示已确认的终态与结果 |

映射时优先处理实际失败、暂停、停止和中断事实，再使用通用 completed。Smart Capture 的整体状态与当前批次阶段一起解释；批次完成不等于整轮完成。未知阶段保留服务端 message，避免自行推断完成。

## 6. 旧进度条结论：保留有效逻辑并统一展示

现有 captureProgressVisible 和 progressPercentage 绑定 custom Store，不能直接作为两种模式的总进度。

本次保留进度条的有效计数逻辑，整合到共用任务状态组件：

- 列表阶段使用实际页数 / 深度等同单位计数。
- 详情阶段使用当前批次的已处理详情数及实际详情目标数。
- 完成数、失败数分别显示；已处理数含失败时明确文案。
- Smart Capture 直接使用该任务或当前批次提供的真实计数，核对计数范围。
- candidate_pool.length 不默认等于本批详情总量；推荐目标也不作为采集进度分母。
- 总量未知时显示阶段和已完成数量，隐藏百分比。
- 列表切换详情时明确显示新阶段，允许阶段百分比重新起算。
- 智能多批次展示当前批次与累计结果；不虚构整轮百分比。
- 停止、失败、中断保留实际计数，不主动补为 100%。
- 正常阶段完成可显示完成标记；整轮完成依据任务状态。
- 清理替换后不再使用的旧计算与样式，页面只保留一套主进度表达。

请求 loading 采用区域遮罩、占位或刷新提示，与采集阶段进度分别呈现。

## 8. 请求区域约定

| 区域 | 当前数据来源 | Loading 与结束处理 |
| --- | --- | --- |
| 浏览器 / 登录 | status、平台会话及启动动作 | 各自结束，错误不阻断已有任务结果 |
| 智能概览与岗位 | current GET、共享快照 | GET 对应区域 loading；实时快照应用不反复闪占位 |
| 自定义概览与岗位 | task 请求及轮询 | 同一次刷新共用请求状态，已有数据局部刷新 |
| 城市 / 策略 / 模型选项 | 现有接口 | 对应表单控件 loading；失败保留输入并提示 |
| 分析队列与结果 | analysis-items | 独立 loading、错误和结果，切换身份时失效 |
| 当前 Context | context-snapshot | 独立 loading；已知缺失显示空态，其他失败显示错误 |
| 历史 Context | 历史对象与通道 | 按历史 ID 和通道独立处理，不能覆盖 current |
| 分析详情 | Item context 请求 | 详情弹窗内 loading；完成后展示内容或错误 |
| 控制按钮 | create / start / pause 等 | 按钮级 loading，超时先同步结果 |

每次请求均处理 success、error、timeout、abort 和失效的 finally。错误后保留同一 owner 的数据，身份切换后不显示上一任务数据。

本次沿用 Context 的已有必要触发语义。先折叠其展示；延迟或取消读取前需确认不会取消当前隐式创建所承担的业务行为。完整纯读迁移在后续 04 中执行。

## 9. 完成标准

对应 08 的 UI 项：

- 智能与自定义的状态、结果和操作归属一致。

- 旧进度条完成整合，不存在重复主进度。

- 每个请求区域完整展示 loading、结果或错误，结束路径均释放。
- 终态结果、已有筛选和详情操作、linked 父镜像及自动分析保持可用。
