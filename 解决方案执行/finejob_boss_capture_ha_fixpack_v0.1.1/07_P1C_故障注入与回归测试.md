## 2. 前端行为验证

### 请求与轮询

- 一次暂态错误后下次成功，轮询继续推进。
- 连续暂态错误有退避与提示，恢复后正常刷新。
- 404、终态、clearTask 和卸载使旧轮询结束。
- 超时、取消和 HTTP 错误释放对应 loading。
- 任务切换后旧响应及旧 finally 不覆盖新状态。
- 写请求响应丢失先同步状态，未自动重复提交。

### 模式和区域

- 智能与自定义各自显示任务、岗位、操作和选择。
- 智能无 current 时不显示 custom 任务数据。
- 请求中没有提前显示空结果；成功无任务后隐藏任务模块。
- 列表采集等待结果、详情采集、失败、停止、完成无结果的展示不同。
- 已有数据刷新保留内容；失败显示区域错误。
- Context、分析队列、分析详情和历史通道分别维护请求归属。
- stopped / paused 即使底层 status 为 completed，也显示真实业务结果。
- 没有可靠分母时隐藏百分比；智能多批次显示实际阶段计数。

### 共享订阅

- App、页面、自动分析控制器共用 current 与 detail。
- 进出页面连接数不增长，终态关闭 detail。
- current 身份切换后忽略旧 detail，GET 与 SSE 竞态按身份和版本处理。
- 断线后恢复最新状态，保留已有岗位。
- 离开页面后自动分析仍可交接，重复快照不重复交接。
- linked 父镜像与历史查询保持边界。

## 3. 后端行为验证

使用替身模拟浏览器和登录结果：

- 参数或容量失败时不执行浏览器启动。
- 浏览器未运行、目标页缺失时执行必要打开。
- available 才允许首次任务创建和实际采集。
- unauthenticated、实际目标重定向、restricted、empty、response_error 分别返回合理结果。
- 同一次启动链路只探测一次。
- pending、resume、retry、继续列表、手动详情入口覆盖实际会启动采集的分支。
- linked 启动遵循父控制权限，检查失败保留已有可恢复身份。
- 既有采集器运行中登录失效和停止行为保持。

服务端真实浏览器操作与自动化用例分开，不在单元用例中依赖真实 BOSS 账号。

## 4. 获批后的实机验收

以用户批准的浏览器与采集环境完成：

1. 无任务进入页面，观察区域加载与配置入口。
2. 浏览器关闭时点击开始；验证自动打开和登录提示。
3. 登录完成后重新点击启动，观察列表到详情阶段变化。
4. 两模式切换，核对任务、列表、操作和选中项。
5. 有结果、零结果、停止、失败分别核对页面。
6. 通过可控网络替身或测试环境模拟慢响应与短暂断线。
7. 离开页面再返回，确认进度恢复及后台自动分析。
8. 核对采集页面及受影响组件的 TypeScript 类型。

真实网站结果受账号和平台状态影响。未能执行的项目记录“未验证”，不能用静态推断替代运行结果。

## 6. 补齐版必需用例

| 覆盖 | 必需场景 | 对应验收 |
| --- | --- | --- |
| 正式 JD 进度 | 三项任务成功/失败/执行中，逐项 SSE 更新；独立任务也可见 | PG-01、PG-02 |

| Codex 入口 | start/continue/details/history 的工具调用经统一检查；一个意图只做一次探测 | ST-06、ST-10 |
