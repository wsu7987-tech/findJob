## 1. 已核实问题

- stopPolling 只清理尚未触发的 timer，已经发出的请求仍可能返回并写入 task、再次安排轮询。

## 2. 请求超时

在 services/api.ts 增加每次调用可指定的 timeoutMs 和外部 signal 支持。先覆盖采集页面初始化、任务读取、控制、浏览器、登录、Context 与分析请求。

- 保持现有调用方式兼容；与采集无关的调用不因本次修改统一套用较短超时。
- 预算覆盖获取响应和读取响应体；后端地址解析也应有明确结束路径，避免请求尚未进入 fetch 就悬挂。
- 区分超时、用户取消、网络错误和 HTTP 错误，提供可显示的错误信息。
- 外部取消立即结束该次等待；finally 清理 timer 和附加 listener。
- 启动浏览器、实时登录探测、同步 AI 分析等调用分别覆盖预算。
- 现有登录探测等待搜索响应的上限为 25 秒，另有 CDP 连接及页面创建等待；原包普通 mutation 的 5～10 秒建议不能直接套用。
- 实施时逐项读取接口内部等待上限，选定有限预算并记录；先用代码约束确定，运行测量须有测试授权。
- 写请求超时只表明响应未知。启动类请求按 14 的 operation_id 查询回执；current/active 仅辅助同步，为空不能判定创建失败，临时容量 ID 不能当作 task_id。其他控制请求查询目标任务状态，禁止直接重复提交。

本次由业务轮询负责读取重试。独立刷新失败时显示错误并提供刷新入口，避免公共请求和轮询叠加重试。

## 3. 自定义轮询

建议最小状态：idle、syncing、retrying；连接错误与 task 业务错误分开保存。

| 结果 | 行为 |
| --- | --- |
| 成功且仍在采集 | 更新当前任务、清除连接错误，按正常周期继续 |
| 网络错误、超时、HTTP 500/502/503/504 | 保留最后成功数据，退避后再请求 |
| HTTP 404 | 停止该任务轮询，显示任务不存在 |
| HTTP 401/403 | 停止自动重试，显示需要处理的请求错误 |
| 其他明确请求错误 | 显示错误及手动刷新入口 |
| 任务终态 | 应用最终结果，停止轮询 |
| clearTask、任务替换、页面卸载 | 结束当前轮询代次，迟到请求无权写回或安排下一次 timer |

沿用正常轮询周期；失败退避可采用 1、2、5、10、15 秒，并加少量随机偏移。成功一次后恢复正常周期。页面活动且任务仍待同步时可继续低频恢复，同时持续显示连接提示。

每个循环捕获任务 ID 和轮询代次。成功、失败、finally 和安排下一次请求前均按归属检查；具体实现保持简洁，复用现有模式。

## 4. 区域请求生命周期

数据区域独立保存 loading、error 和最后成功结果。旧请求完成时，只能释放自己的 loading，不能清除新请求的 loading。

- 首次读取：区域 loading，完成后进入内容、空态或错误。
- 已有数据刷新：保留内容，显示局部刷新提示。
- 超时或错误：结束 loading，保留同一任务已有数据并提示刷新失败。
- 任务或模式改变：清理不属于新 owner 的内容和选择；迟到响应不写入新 owner。
- 页面卸载：取消或使页面请求失效，保留应用级任务数据的生命周期。
- 快照一次返回多个区域的数据时，共享请求事实，由各区域独立渲染；不要求新增 jobs 请求。

## 5. 控制请求

- 点击后立即设置按钮 loading，包括容量检查、浏览器检查和登录检查。
- 控制按钮 loading 与概览、列表的 loading 分离。
- create、start、pause、resume、stop、retry 不做通用自动重放。
- 响应未知时查询回执/权威状态；网络 spinner 结束但未决意图锁保留。unknown、查询 404 或网络失败不允许换 ID 再创建，具体恢复规则见 14。
- 当前 transition_id 接口继续保留；本次按 14 实施启动意图的持久化回执与有限去重，暂停/停止等完整控制幂等仍见后续 04。

## 6. 授权后的验收

对应 08 的 RQ、PL、RC 项：

- 首次失败后能继续同步；连续暂态失败仍有明确状态。
- 404、终态、卸载和任务切换能结束旧轮询。
- timeout、abort、HTTP 错误均释放对应 loading。
- 晚返回的旧数据与旧 finally 不覆盖新请求。
- 写请求响应丢失不会被自动提交第二次。
- 浏览器和登录调用使用独立预算，不被短超时提前终止。

交付记录包含采集接口预算表和请求重试归属；当前阶段仅编写计划。


## 7. 请求层补充细节

- 超时覆盖 origin 解析、fetch 和响应体读取；`parseJsonSafely` 不能吞掉响应体 AbortError 后返回 null 并冒充成功。成功响应损坏需报告协议错误。
- 外部 signal 已取消时不发送请求；组合取消与 timeout 后清理 listener/timer。origin Promise 失败后允许下一次请求重新解析，不能永久缓存失败。
- 01 只提供 HTTP 等待和轮询基础；14 提供未决启动恢复。不能因 finally 把 starting 设为 false，就同时解除结果未确认的提交锁。
- 预算表逐项填写：入口、origin 预算、CDP/探测/响应体上限、总超时、重试归属、超时确认入口。没有读取完内部等待上限前，不宣称某个统一数字足够。
