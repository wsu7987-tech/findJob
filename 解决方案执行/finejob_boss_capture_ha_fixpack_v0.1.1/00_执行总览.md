# 岗位采集业务与页面优化执行总览

## 1. 本次目标与授权

本包围绕用户的六项要求实施：列表与详情采集状态可见、整理旧进度条、区分智能与自定义模式、启动前自动打开浏览器并检查登录、按业务状态显示区域、请求结束后正确结束区域 loading。

当前已获准完善本任务包文档。代码修改、编写或运行测试、类型检查仍须获得用户后续明确批准。文档中的实施步骤与验收用例均为待执行计划。

原包目录及文件名保留，正文范围以本总览为准。文件编号仅用于定位，执行顺序见第 4 节。

## 2. 静态核对结论

| 项目 | 当前实现依据 | 本次处理 |
| --- | --- | --- |
| 自定义轮询单次失败后停止 | fineJobBossCapture.ts 的 refreshTask、startPolling | 修复瞬时失败恢复、任务切换与停止后的迟到响应 |
| 公共请求没有统一超时能力 | services/api.ts 的 request | 增加可配置超时，先为采集链路指定预算 |
| 旧进度条继续使用 | BossCapture.vue 的 captureProgressVisible、progressPercentage | 保留有效进度逻辑，整理为两种模式共用的一套展示 |
| 概览读取自定义状态 | captureOverview 固定读取 captureStore.task | 按当前模式选择任务，再生成展示状态 |
| 模式间可能串数据 | workflowDisplayJobs 在智能模式无 current 时回退到自定义任务 | 明确 owner，切换模式时同步切换列表、操作和选中项 |
| 智能区域显示边界不完整 | 智能摘要、Planner、分析等区域位于模式标签之外 | 专属区域按模式和任务可用性显示 |
| 空列表无法完整展示 | 岗位列表外层以 workflowDisplayJobs.length 控制 | 建立 loading、error、empty、content、hidden 条件 |
| 活动任务可能有四条 Smart Capture SSE | 页面及 fineJobWorkflowCodexController.ts 各自创建 current 和 detail | 应用级共享一套 current + 活动 detail |
| current SSE 主要推送身份变化 | publish_smart_capture_snapshot 仅在 current_pointer_changed 时 publish_current | 保留 detail 承担任务进度更新 |
| 页面已处理终态 detail 关闭 | applyCurrentSmartCapture、openSmartCaptureDetailEventSource | 保留现有能力，检查共享后的生命周期 |
| 手动浏览器和登录能力已有实现 | platform_sessions.py、boss_scraper/service.py | 复用底层能力串联启动流程 |
| 登录探测已经提供结构化结果 | boss_cdp_raw.py 的 LoginProbeStatus | 保留未登录、受限、空样本、异常的区别 |
| Context GET 可能创建快照 | smart_capture_domain.py 的 get_context_snapshot | 本次保留接口语义，排除通用自动重试，迁移另列后续 |
| 控制接口已有 transition_id 入口 | smart_captures 路由与服务 | 本次保持控制语义，不自动重放写请求 |

以上为代码静态核对，尚无本轮运行验证或性能测量结果。

## 3. 本次范围和后续范围

### 本次实施

- 采集请求有界等待、自定义轮询恢复、请求状态归属与迟到响应处理。
- 列表采集、详情采集、暂停、停止、失败、完成等业务阶段映射。
- 智能、自定义和共用区域整理；旧进度条收敛；区域 loading、错误、空态。
- 启动时浏览器及目标页面检查、必要时打开、实时登录校验。
- 页面与全局自动分析控制器共享实时订阅，断线恢复时重新读取权威状态。
- 针对本次改动的前后端回归与类型检查，获得测试授权后执行。

### 后续独立立项

- 单条 SSE 主流、增量事件、事件序号及缺口恢复协议。
- overview 与大集合拆分、岗位和候选池服务端分页。
- Context 纯读迁移、完整控制幂等链路。
- 系统级健康接口、性能指标和大规模故障注入。

后续项不作为本次页面优化的前置条件。本次交付结论仅覆盖本次验收矩阵；全量快照的传输和构建成本仍保留。

## 6. 保持的业务语义

- current 身份来自服务端 current 接口与 current 流；历史查询不改变 current。
- 同一任务保留 state_version 比较；切换任务同时检查身份和请求代次。
- linked Smart Capture 遵循父 Workflow 控制能力；全局自动分析继续在离开页面后工作。
- 自定义和智能采集共用的执行容量约束继续生效。
- 暂停、停止、失败按实际 status、stage、control_status 等映射。
- 数据库结构、采集核心状态机、搜索策略及分析编排保持原有职责。
