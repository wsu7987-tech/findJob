# 岗位采集与驾驶舱状态修复记录

## 1. 问题现象

1. 进入岗位采集页面后短时间内产生较多请求，页面内容持续变化。
2. 岗位采集与任务驾驶舱会继续展示上一个任务的执行态，包括已经结束的任务。
3. 驾驶舱可能同时显示“父任务状态：active”和“父任务已结束”，并提供无法执行的暂停按钮。

## 2. 原因定位

### 2.1 岗位采集重复刷新

- 岗位采集页面先加载浏览器、城市、策略、平台会话和 Codex 模型，再读取 current Smart Capture。模型目录读取较慢时，页面会长时间保留共享 Store 中的旧状态。
- current API 已返回完整 Smart Capture 快照，页面仍会按 ID 再读取一次详情。
- Smart Capture 每次 `state_version` 增长都会重新读取 Context 和 Analysis。采集进度会高频更新版本，因此产生重复请求。
- 页面离开时只停止自定义采集轮询，没有停止关联父任务的 Workflow SSE。

### 2.2 驾驶舱恢复已完成任务

- 驾驶舱挂载时使用 `includeCompleted=true` 恢复 latest Workflow Run，导致已完成任务再次进入当前状态区域。
- 页面离开时没有停止 Workflow SSE，共享 Store 会继续接收上一个任务的快照。

### 2.3 生命周期与控制状态混用

- 驾驶舱状态标题展示的是 `control_state`，任务结束与否实际由 Workflow `status` 决定。
- 完成后的父任务允许保留 `control_state=active`，页面仅按这个字段显示暂停按钮，点击后才由后端拒绝。

## 3. 修改内容

### 3.1 岗位采集页面

- 页面进入时先停止旧 Workflow SSE，并清空旧父任务镜像。
- 已结束的自定义采集任务不再作为当前执行态恢复。
- current Smart Capture、基础选项和 Codex 配置并行加载，current 状态不再等待模型目录请求。
- current API 的完整快照直接用于页面初始化，取消紧随其后的重复详情读取。
- Context 和 Analysis 改为在 Smart Capture 身份、状态、阶段、当前批次或等待原因变化时刷新；单纯进度版本增长不再触发这两类请求。
- Context 与 Analysis 使用并行读取。
- 页面离开时同时停止自定义采集轮询、Smart Capture SSE 和 Workflow SSE。
- Smart Capture 终态保留为“最近任务结果”，关闭采集控制并继续保留 completed 后的 Manual Analysis 能力。

### 3.2 任务驾驶舱

- 页面进入时先停止旧订阅并清空共享 Store 中的旧父任务快照。
- latest 查询改为只恢复非终态的 `task_cockpit` 任务。
- Workflow 恢复与策略、配置读取并行启动，减少慢配置请求造成的旧状态停留。
- 页面离开时停止 Workflow SSE。
- 状态标题展示 Workflow 生命周期 `status`，控制状态独立显示；终态统一显示为“已结束”。
- 暂停、继续按钮增加非终态条件，停止按钮沿用非终态条件。

### 3.3 Workflow Store

- `pause`、`resume`、`cancel` 在父任务终态时直接返回当前快照，不再请求后端控制接口。

## 5. 预期结果

1. 进入岗位采集页面后优先显示服务端 current 状态，不再先显示上一次父任务快照。
2. 高频采集进度更新只更新 Smart Capture 主快照，不重复请求 Context 和 Analysis。
3. 重新进入驾驶舱时，有活动任务则展示活动任务，没有活动任务则展示新任务编排区。
4. 父任务终态不显示暂停、继续或停止操作，也不会从 Store 调用对应后端接口。
5. 已结束 Smart Capture 以“最近任务结果”展示，采集控制关闭，执行态与历史结果语义分开。
