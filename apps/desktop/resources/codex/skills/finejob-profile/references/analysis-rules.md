# 分析规则

## 事实

- 一个字段表达一个可独立确认的事实。
- 多段工作、教育和项目经历使用稳定的 `entity_id` 分组，并用 `sort_order` 排序。
- 日期精度与正文一致，只有年份时使用 `year`，只有年月时使用 `month`。
- 正文明确支持且无冲突的事实默认确认；正文没有提供或存在冲突的内容进入待处理问题。
- `source_excerpt` 使用能直接支撑事实的最短原文片段。
- 事实绑定当前简历组；确实适用于所有简历的候选人基础信息才使用通用作用域。

## QA 与回答版本

- 优先检查所在地、可接受城市、目标岗位、期望薪资、到岗时间、离职原因、当前薪资和学历信息。
- 已存在默认问题时复用相同 `question_key`，避免生成同义重复问题。
- 有明确原文答案的 QA 默认确认；答案缺失、不确定或冲突时保持待处理。
- 当前薪资、离职原因等默认禁止披露，用户可直接调整披露级别。
- 新建问题必须选择简历组或通用作用域，预设问题提取答案时沿用当前简历组。
- 岗位专用回答只适用于当前 `job_id`；提升为岗位族版本由用户确认。
- 不用编造经历来迎合 JD。资料不足时明确提出待确认问题。

## 搜索和策略

- 搜索词可有多个，分别覆盖核心岗位名、技能组合和相近岗位族。
- 搜索词按执行优先级排序，第一项作为默认搜索词。
- 城市、薪资和工作方式缺失时通过 QA 获取，不自行设定。
- 排除词基于资料目标和明显不匹配方向生成，并提供简短原因。
- 策略内容应能被岗位搜索、岗位评估或 HR 沟通直接执行。
- 已确认事实和 QA 是策略硬约束，规范 Markdown 用于补足经历语境；两者冲突时生成待处理问题。
